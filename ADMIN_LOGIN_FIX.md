# Fix for `/admin/login` with your current Supabase schema

Your screenshots show `public.admin_users` has:

- `id` (int8)
- `user_id` (uuid)
- `created_at` (timestamptz)

So any SQL that references `admin_users.is_active` or `admin_users.role` will fail.

## Why your current login fails

Your frontend is querying columns like `role` / `is_active` from `admin_users` or `profiles`, but those columns do not exist in your current DB tables.

That causes PostgREST to return `400 Bad Request`.

---

## Correct approach for your current table

Use **admin row existence** as the admin flag:

- If a user has a row in `public.admin_users`, that user is admin.
- If no row exists, user is not admin.

## 1) Run this SQL in Supabase

```sql
-- Make sure admin_users has the columns your app needs (based on your screenshots)
create table if not exists public.admin_users (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users(id) on delete cascade,
  created_at timestamptz not null default now()
);

-- If table already existed, keep it safe
alter table public.admin_users
  add column if not exists id bigint generated by default as identity,
  add column if not exists user_id uuid,
  add column if not exists created_at timestamptz not null default now();

-- Ensure user_id is required
alter table public.admin_users
  alter column user_id set not null;

-- Avoid duplicate admin rows for same user
create unique index if not exists admin_users_user_id_uidx
  on public.admin_users (user_id);

-- Enable RLS
alter table public.admin_users enable row level security;

-- Allow authenticated user to read only own admin row
drop policy if exists "admin_users_select_own" on public.admin_users;
create policy "admin_users_select_own"
  on public.admin_users
  for select
  to authenticated
  using (auth.uid() = user_id);

-- RPC function: user is admin if row exists
create or replace function public.is_admin(p_user_id uuid)
returns boolean
language sql
security definer
set search_path = public
as $$
  select exists (
    select 1
    from public.admin_users
    where user_id = p_user_id
  );
$$;

revoke all on function public.is_admin(uuid) from public;
grant execute on function public.is_admin(uuid) to authenticated;
```

## 2) Add admin manually (your workflow)

```sql
insert into public.admin_users (user_id)
values ('<auth_user_uuid>')
on conflict (user_id) do nothing;
```

To remove admin access:

```sql
delete from public.admin_users where user_id = '<auth_user_uuid>';
```

## 3) Frontend login flow (recommended)

```ts
const { error: signInError } = await supabase.auth.signInWithPassword({
  email,
  password,
});
if (signInError) throw signInError;

const {
  data: { user },
  error: userError,
} = await supabase.auth.getUser();

if (userError || !user) {
  await supabase.auth.signOut();
  throw new Error('Unable to verify user');
}

const { data: isAdmin, error: adminError } = await supabase.rpc('is_admin', {
  p_user_id: user.id,
});

if (adminError || !isAdmin) {
  await supabase.auth.signOut();
  throw new Error('You do not have admin access');
}

// success
router.push('/admin');
```

---

## Important note for your app now

Do **not** query these columns until you actually add them:

- `admin_users.role`
- `admin_users.is_active`
- `profiles.role`
- `profiles.is_active`

If you later want role levels (`owner`, `staff`) and enable/disable admin, then add those columns in a new migration and update the RPC accordingly.
